# FriendCircle API (v0.1)

Base: `/api`. JSON requests use `Content-Type: application/json`. Authentication uses an HTTP-only `fc_token` cookie obtained by signing in. Requests must be same-origin; no public cross-origin API access is enabled. This is first-party API documentation, not a third-party OAuth integration. Errors return `{ "error": "message" }` with 400/401/403/404/429 as appropriate. Photo upload uses multipart. All responses are private/non-cacheable.

An encrypted direct message:

```json
{
  "kind": "encrypted",
  "ciphertext": "base64 AES-GCM ciphertext and authentication tag",
  "iv": "base64 12-byte nonce",
  "senderKey": { "kty": "EC", "crv": "P-256", "x": "...", "y": "..." },
  "recipientKey": { "kty": "EC", "crv": "P-256", "x": "...", "y": "..." }
}
```

The browser derives an AES-GCM 256-bit key using ECDH P-256. See `lib/crypto.ts`; private keys are never transmitted. The API verifies envelope keys against registered keys. No plaintext direct-message endpoint exists. Group messages use the same cipher separately for every member.

Chat allowance is decremented by encrypted payload UTF-8 bytes (AES-GCM tag excluded); this lets the server enforce it without seeing text. ASCII uses one allowance unit per character; multi-byte Unicode uses more. Accepted public chat requests provide 300 units to each participant; existing friends use their meeting-earned balance. Both users must be accepted friends with fresh location samples within 50 m for a continuous meeting timer. Every 10 minutes grants each 100 units and 5 social credits. The demo does not award from illustrative positions. Friend discovery uses the current suburb; Catch up restaurant discovery uses a fixed 5 km radius, neither purchasable. Bundled ABS suburb boundaries currently cover the Perth metropolitan demo area.

Socket.IO connects on the same origin and authenticates the session cookie. The `refresh` event contains no personal data; it tells clients to refetch authorized endpoints. Server sends refresh after changes and every 30 seconds. No client may broadcast arbitrary socket payloads to other clients.

Verification lifecycle: `review → pending → accepted/rejected`. A high-confidence two-face result starts at `pending`. Only reviewers approve `review`, and only recipients accept `pending`. Requests expire after 24 hours. Photos are deleted after final decisions or expiry (immediate on recipient decision, otherwise by the next one-minute cleanup sweep). Metadata remains for history. Detection is not identity verification.

The private verifier exposes `POST /verify` with a multipart `photo` and `Authorization: Bearer <private token>`. Response: `{faceCount:number,confidence:number}`. It must not be internet-exposed.
